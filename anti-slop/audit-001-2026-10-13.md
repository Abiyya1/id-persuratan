# Audit Cari Surat — 13 Oktober 2026

Status: audit-first dipilih pengguna; nomor 1–4 telah disetujui dan diimplementasikan. Identitas/sidebar desktop serta alokasi nomor tetap; navigasi hanya membungkus di atas konten pada layar kecil agar tidak overflow.

## 1. Tanggal dibuat — permintaan fitur
Prioritas MEDIUM; C-3 (informasi sesuai kebutuhan pengguna), bukan klaim bug lama.
Sumber: DocumentRow.created_at sudah tersedia; DocumentsTab saat ini menampilkan surat_number lalu letter_date.
Usulan: tambahkan Tanggal dibuat di antaranya; tampilkan tanggal dan jam penggunaan nomor oleh surat saat ini dalam WIB. Gunakan created_at, bukan tanggal surat atau waktu sinkronisasi. Bila nomor dipakai ulang oleh surat baru, tampilkan waktu surat baru dibuat.

## 2. Sort tiga kolom — permintaan fitur
Prioritas MEDIUM; C-2/R-26 (kontrol baru harus bekerja end-to-end).
Sumber: API documents/list hanya mengurutkan created_at descending; belum ada pilihan sort di DocumentSearch/DocumentsTab.
Usulan: Nomor Surat, Tanggal dibuat, Tanggal, masing-masing ascending/descending. Sort dilakukan di backend sebelum pagination, dengan urutan stabil dan tanggal kosong di akhir. Nomor diurutkan secara numerik/natural, bukan string leksikografis; nomor bersufiks tetap dipertahankan. Default tetap tanggal dibuat terbaru.

## 3. Overflow horizontal — temuan nyata
Prioritas HIGH; R-03/C-4 (informasi tidak terpotong dan layout reflow).
Sumber: screenshot memperlihatkan kolom Tindakan terpotong. DocumentsTab menggunakan overflow-x-auto serta banyak sel whitespace-nowrap dan tombol teks panjang.
Usulan: tabel desktop lebar terkontrol, tanggal/jam pada dua baris, teks panjang dapat membungkus; layar sempit memakai daftar/kartu berlabel dengan urutan informasi yang sama. Semua informasi tetap tersedia; tidak menyembunyikan data dengan overflow-hidden, mengecilkan teks berlebihan, atau memangkas isi surat. Penyuntingan, status, pagination dan konfirmasi hapus tetap bekerja.

## 4. Ikon tindakan — permintaan fitur
Prioritas MEDIUM; R-04/R-25/R-32 (ikon relevan, warna terukur, keyboard dan nama aksesibel).
Sumber: tombol Sunting/Sinkronkan ulang/Hapus saat ini menggunakan label teks dan memakan lebar tabel.
Usulan: SVG Heroicons MIT yang di-inline, tanpa dependency baru: pensil untuk edit, arrow-path hijau untuk sinkronisasi, trash merah untuk hapus. Pertahankan tooltip, aria-label, fokus keyboard, disabled/busy state dan konfirmasi penghapusan. Ukuran target cukup untuk sentuhan.
Referensi primer: https://github.com/tailwindlabs/heroicons

## Batas perubahan
Tema navy/putih dan bahasa Indonesia dipertahankan. Tidak menghapus field, mengubah kepemilikan surat, menggeser nomor, atau menulis Supabase/Sheets produksi. Kolom waktu memakai data yang sudah ada; sort numerik akan mengikuti skema yang tersedia, dan bila perlu migrasi akan diberikan sebagai file untuk aktivasi pengguna, bukan diterapkan diam-diam.

## Delivery gate — PASS
Tanggal dibuat WIB dan enam arah sort telah diuji melalui komponen/API aktual dengan transport fixture terisolasi. PostgreSQL lokal memverifikasi urutan numerik, suffix, pagination, ties/null dan izin service-only/security-invoker. Halaman dan tabel tidak overflow horizontal pada lebar 320, 390, 720, 768, 1024, 1280 dan 1440px; semua field tersedia. Ikon mempunyai nama aksesibel, fokus dan target 44px; kontras hijau telah diperiksa. Sunting/simpan, polling-preserved edit, respons sort terlambat, archive readonly, batal/konfirmasi hapus dan status pelepasan tertunda telah dijalankan. Unit, typecheck dan lint lulus; reviewer UI/SQL tidak menemukan defect tersisa. Tidak ada dependency baru, perubahan environment atau penulisan produksi. Aktivasi sort nomor memerlukan pengguna menjalankan migrasi 20261011_document_sort.sql yang disediakan.
